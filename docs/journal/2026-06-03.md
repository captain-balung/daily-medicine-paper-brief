# Journal - 2026-06-03

Today the project crossed from prototype into a usable Core MVP.

The most important product decision started as keeping the first public version text-first. That let the project focus on the core loop first: collect medical literature, enrich metadata, analyze with Anthropic, publish a readable daily briefing, and generate a podcast-ready script. After physician feedback said the script was good, the project moved into the next stage and added OpenAI TTS audio.

The Render Cron setup was the operational turning point. The pipeline no longer depends on the user's computer being on. A manual one-off Render job succeeded and proved that the cloud worker can collect, enrich, analyze, and publish through Supabase.

The podcast work now has a complete first audio loop. The system can generate a script, split long scripts for the OpenAI TTS input limit, create MP3 audio, upload it to Supabase Storage, and show an audio player on the web page. The first generated audio was tested on production and the user confirmed they could hear it.

After the audio loop worked, the next useful step was trust and operability. Article cards now explain why an article was ranked, including total score, strongest scoring signal, recommendation label, access-status explanation, and the AI scoring rationale. The confusing `UNKNOWN` access label is now rendered as `Full text unknown`. A lightweight `/admin/status` page now shows recent pipeline jobs and whether the latest briefing, podcast script, and audio exist.

The next browsing-efficiency layer is now in place. Homepage and daily pages include a `Today's Top Ranking` table so readers can scan the selected papers before reading individual cards. The article list can be filtered by access status, article type, minimum score, and sorted by score, clinical impact, or publication date. This should make physician review faster because the same article set can be sliced without needing a separate admin tool.

Current confidence is good for the MVP loop:

- Web: stable enough for friend review.
- Data pipeline: working.
- Render automation: configured and tested once.
- Podcast script: working as text.
- Podcast audio: working with OpenAI TTS when `OPENAI_API_KEY` is configured.
- Ranking rationale: visible on article cards.
- System status page: working at `/admin/status`.
- Top Ranking summary: visible on homepage and daily pages.
- Article filters: working on `/articles`.

Main risks:

- The first scheduled Render run with audio should be checked after tomorrow morning.
- AI ranking, podcast tone, and TTS voice still need physician calibration.
- Ranking rationale wording may need physician calibration.
- Logs are still mostly developer-facing; there is no admin dashboard.

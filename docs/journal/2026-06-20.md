# Journal - 2026-06-20

The reported symptom was narrow but the cause was a classic environment gap: the daily online videos were fine everywhere except the screenshots, where Chinese turned into tofu boxes. English was untouched, which was the first strong hint — this was a font coverage problem, not a data or encoding problem.

Tracing the slide rendering led straight to `generate_podcast_video.py`. The slides are drawn with Pillow, and `_load_font()` walked a candidate list that worked beautifully on the developer's Windows machine (it found `msjh.ttc`) but had nothing usable once it ran on Render's Linux cron. The probed Noto CJK paths were never installed — the worker requirements only pull in `pillow` and `imageio-ffmpeg`, and Render's native Python runtime has no `apt` step to add system fonts. So the loader quietly fell through to DejaVuSans, which has no CJK glyphs. Local-looks-fine, cloud-is-broken: the most deceptive kind of bug.

The fix was deliberately boring and self-contained. Rather than depend on the host having the right font, the font now travels with the code: Noto Sans CJK TC is vendored into `workers/assets/` and inserted into the search order ahead of the system paths, so it works whether or not `VIDEO_FONT_PATH` is set. The env var was added to `render.yaml` and `.env.example` as belt-and-suspenders, and because both local and cloud now use the same font, the layout will be identical across environments. The bundled font added ~16MB to the repo, which is a fair trade for determinism.

The second half was cleanup. Every video produced before today carried the same garbled text, so a one-off backfill script re-rendered all 15 prior daily videos, overwriting the storage objects in place. Verification was done against the real cloud artifacts, not just local output: the uploaded MP4s were pulled back from Supabase and frames extracted to confirm the Chinese renders. All clear.

The broader lesson echoes the 2026-06-05 entry: this product keeps getting bitten by the gap between the Windows dev box and the Render Linux runtime — first missing Python packages, now missing system fonts. The durable answer is to stop assuming anything about the host. Vendoring the font is one instance of that principle; a small preflight that asserts font and dependency readiness before the daily run would generalize it.

Recommended next work:

1. Watch the next automatic Render cron run and confirm the freshly-generated video has correct Chinese end-to-end.
2. Decide whether overwriting videos under stable names needs cache-busting for the front-end/CDN.
3. Consider a preflight check that verifies a CJK-capable font (and `PIL`/`imageio_ffmpeg`) before rendering, so environment gaps surface early rather than as garbled output.
4. Optionally automate the log/journal habit via a Claude Code hook so it stops drifting.
